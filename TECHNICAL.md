# Technical Document — SAR ADC Simulator

This document describes the architecture, the mathematical models, the
measurement methodology and the limitations of the simulator. It is the
authoritative reference for every equation and assumption used in the code.

---

## 1. Architecture overview

```
  waveform (analytic sine)
        │
        ▼
  SAMPLE & HOLD  ──►  sampling jitter (aperture view)
        │              finite acquisition time (RC settling)
        │              optional slew-rate nonlinearity
        ▼
  v_held[k]  (clamped to the input range)
        │
        ▼
  SAR CONVERTER (N cycles per conversion)
        │    comparator:  keep ⟺ (v_held + v_off + noise) ≥ v_dac(trial)
        │    DAC:         v_dac(c) = Vref_actual · Σ b_i(c)·w_i / (Σ w_i + 1)
        ▼
  code[k] ──► ideal digital decode (midpoint / code) ──► recon[k]
        │
        └──► metrics: INL, DNL, SNDR, THD, SFDR, ENOB, latency
```

Two independent "converter" objects exist:

* `IdealADC` — the theoretical ideal quantizer. Sample-and-hold is
  instantaneous, no nonidealities of any kind. Used as the reference.
* `SARConverter` — the explicit circuit model. Every conversion runs the SAR
  binary-search algorithm cycle by cycle against the (possibly mismatched)
  DAC and the (possibly noisy, offset) comparator.

The two share the same code conventions so they can be compared on identical
test signals.

## 2. Quantization model

### 2.1 Resolution, LSB, coding conventions

For `N` bits (`4 ≤ N ≤ 16`) and a reference `Vref`, the ideal code step is

```
LSB = Vref / 2^N
```

The analog input range is `[v_min, v_max]` with `v_max − v_min = Vref`.
Internally the converter works on the shifted domain `s = v − v_min ∈ [0, Vref]`.

Coding conventions:

* **offset_binary** (unsigned): `code ∈ [0, 2^N − 1]`.
* **twos_complement** (signed bipolar): `code = offset_binary − 2^(N−1)`.

Transfer styles:

* **mid-rise** (the natural SAR structure): transition from code `k` to `k+1`
  at `s = k·LSB`; code `k` covers `[k·LSB, (k+1)·LSB)`.
* **mid-tread**: transition at `(k + 1/2)·LSB`; true zero code. Implemented by
  shifting the comparison domain by `+LSB/2` before a mid-rise conversion
  (`midtread code = midrise code of (v + LSB/2)`).

Reconstruction of a code `k`:

* **midpoint** (default): `recon = (k + 1/2)·LSB` for mid-rise (minimum-error
  decode).
* **code**: `recon = k·LSB` (threshold decode).

Inputs outside `[v_min, v_max]` saturate (clip), which is flagged in the trace.

### 2.2 Ideal quantization error

For a uniform input density and midpoint reconstruction, the quantization
error `e = v − recon` is uniform on `[−LSB/2, +LSB/2)`:

```
σ_e = LSB/√12 ≈ 0.2887·LSB
```

A full-scale sine (`amp = Vref/2`) through an ideal `N`-bit mid-rise quantizer
has the classic SNR:

```
SNR_ideal = 6.02·N + 1.76  dB        (quantization noise only, white)
```

This is the theoretical anchor used in the verification.

## 3. Successive-approximation algorithm

For one conversion the SAR executes exactly `N` comparison cycles, MSB first:

```
reg := 0
for i = N−1 down to 0:
    trial    := reg | (1 << i)                  # set the trial bit
    v_trial  := V_DAC(trial)                    # DAC settles to trial voltage
    keep     := (s − v_trial) + v_off + noise ≥ 0    # comparator strobes
    if keep: reg := trial                       # latch the bit, else clear it
```

After the loop, `reg` is the digital code. The code is **not** produced by
rounding the input: each bit is independently decided against the actual DAC
voltage generated by the register so far. With an ideal DAC and no
comparator offset this reduces exactly to `code = floor(s/LSB)` (verified in
the test suite over 20 000 random inputs).

Per-cycle state exposed by the trace: `bit_index`, `trial_code`,
`trial_voltage`, `comparator_input`, `decision`, `register_code`,
`register_voltage`, `residual = s − v_dac(register)`.

The bulk path (`convert_bulk`) runs the same loop vectorised over an array of
samples using a precomputed DAC voltage lookup table (length `2^N`), so
metrics and transfer curves over 65 536 samples × 16 bits complete in well
under a second while remaining bit-identical to the scalar path when the
comparator is deterministic.

## 4. DAC model — binary-weighted capacitive array

### 4.1 Ideal transfer

The DAC models a charge-redistribution array of `N` binary-weighted
capacitors `C_i = 2^i·C_u` plus one termination capacitor `C_u`:

```
V_DAC(c) = Vref_actual · Σ_i b_i(c)·C_i / (Σ_i C_i + C_u)
         = Vref_actual · Σ_i b_i(c)·w_i / (W + 1)
```

with `w_i = 2^i` and `W = Σ_i w_i = 2^N − 1` in the ideal case. The `+1`
termination capacitor makes the ideal step exactly `LSB = Vref/2^N` and the
full-scale code exactly `(2^N − 1)·LSB`, consistent with §2.1.

### 4.2 Capacitor mismatch

Mismatch makes each weight deviate from its ideal value:

```
w_i = 2^i · (1 + ε_i),     ε_i ~ N(0, σ_u)
```

where `σ_u` is the relative standard deviation of the unit capacitor. The
denominator uses the *actual* total capacitance (physically correct for
charge redistribution), so the transfer is normalized but retains the gain
error and the per-code nonlinearity. Uncalibrated binary-weighted arrays
produce transition-level errors that grow with the largest bit, so with
`σ_u = 1%` and `N = 12` the mid-scale INL is on the order of `2^11·σ_u ≈ 20 LSB`
— this is real physics (it is why real SARs use small unit caps, averaging,
calibration or stochastic redundancy).

### 4.3 Reference-voltage error

```
Vref_actual = Vref · (1 + g)
```

`g` is a pure gain error: every transition `T[k] = V_DAC(k) − v_off` scales
by `(1 + g)`. A positive `g` also makes the top code unreachable for inputs
`≤ Vref` (input-range/reference mismatch), which is reflected in the
endpoint-fit INL.

## 5. Comparator model

```
decision:  keep  ⟺  (s − v_trial) + v_off + v_n ≥ 0
v_n ~ N(0, σ_c)
```

* `v_off` — DC offset. Shifts every decision threshold by `−v_off`, i.e. the
  converter behaves as if the input were `s + v_off` (an input-referred
  offset, removable by system calibration).
* `σ_c` — RMS noise. With Gaussian noise the bit error probability is
  `Q(margin/σ_c)` where `margin = (s − v_trial) + v_off`. Comparator noise
  adds a roughly Gaussian error to the digitized value and appears as a noise
  floor in the spectrum.

## 6. Sample-and-hold model

### 6.1 Sampling jitter (aperture view)

The nominal sample time `t_k = k/fs` is perturbed:

```
t'_k = t_k + δ_k,      δ_k ~ N(0, σ_t)
s_k  = v(t'_k)
```

The signal is evaluated at the *actual* aperture instant (analytic wave
evaluation), which is the correct first-order view of clock jitter. For a
sine of amplitude `A` and frequency `f` the sampled phase error has RMS

```
σ_v ≈ A·2π·f·σ_t
```

so the jitter-limited SNR is `SNR_j ≈ 1/(2π·f·σ_t·(A/Vref))` — the familiar
aperture-jitter formula.

### 6.2 Finite acquisition time

The track switch closes `T_acq` before the sampling instant. The capacitor
charges from the previously held value toward the instantaneous input with
time constant `τ`; the residue at the instant the switch opens is:

```
v_held[k] = v(t'_k) − [v(t'_k) − v_held[k−1]] · exp(−T_acq/τ)
```

With `τ = 0` or `T_acq → ∞` this is exact tracking (ideal S/H). The
settling error scales with the sample-to-sample signal excursion, i.e. with
slew rate — hence with input frequency. For a single tone this is mostly an
amplitude/phase (memory) effect; combined with the optional nonlinearity
below, or with multi-tone input, it generates distortion.

### 6.3 Input-frequency-dependent distortion (optional model)

A simplified behavioral term models slew-rate-dependent S/H nonlinearity:

```
v_held += k_slew · (dv/dt)²
```

`(dv/dt)²` of a single tone contains `2·f` content, so this term produces a
second harmonic whose level grows with input frequency. This is explicitly a
behavioral (not transistor-level) distortion mechanism.

## 7. Performance metrics — methodology

### 7.1 Transition levels, INL and DNL

Define the transition levels `T[k]` (`k = 1 … 2^N − 1`) as the input voltage
at which the output code first reaches `k`. Two equivalent methods:

* **Analytical (used for the SAR model).** Because the SAR compares against
  actual DAC voltages and (with a monotone weight set) yields the *largest*
  code whose DAC voltage is not above the input, the transition is exactly

  ```
  T[k] = V_DAC(k) − v_off      (mid-rise, shifted domain),   T[0]=0, T[2^N]=Vref
  ```

  This is O(2^N), exact for the model, and is cross-validated against the
  ramp method in the tests.
* **Ramp measurement (generic).** Feed a dense ramp (default 16 samples per
  code), find the first input producing code `≥ k`, linearly refine. Used for
  the ideal quantizer module and as the cross-check.

DNL and INL (in LSB, per code):

```
DNL[k] = (T[k+1] − T[k])/LSB − 1          k = 0 … 2^N − 2   (last bin: k=2^N−1)
INL_ep[k]  = Σ_{j≤k} DNL[j]  (endpoint-fit, zero at both ends)
INL_bf[k]  = (T[k] − k·LSB)/LSB  minus best-fit line through (k, T[k]−k·LSB)
```

`Σ DNL` over the full span equals the endpoint gain error. The best-fit
version absorbs gain/offset and isolates nonlinearity. The reported
`gain_error_frac` is the best-fit slope minus 1 (fractional).

### 7.2 SNDR, SNR, THD, SFDR, ENOB

Measurement procedure (IEEE-1241-style, documented for reproducibility):

1. **Coherent test record.** The tone has exactly `M` integer cycles in `n`
   samples (`M` odd, `M < (n/2)(1 − margin)`), so the fundamental lands on an
   exact DFT bin and there is no spectral leakage of the tone.
2. **Windowing.** Optional Hann window is applied (default). With coherent
   sampling the tone power is captured in the mainlobe (±`signal_band = 2`
   bins); the window's energy scaling affects signal and noise nearly equally,
   preserving the SNDR ratio (verified by comparing windowed vs. unwindowed
   results in the test suite).
3. **Bin classification** (using `rfft` power, doubled for the positive
   frequencies):
   * *signal bins*: mainlobe around the detected fundamental;
   * *harmonic bins*: mainlobe around `2·f … n_harm·f` (up to 6), each
     excluded from noise;
   * *discarded*: the lowest 4 bins (DC/leakage);
   * *noise+distortion*: everything else.
4. Definitions:

```
P_sig   = Σ|X|² over signal bins
P_harm  = Σ|X|² over harmonic bins
P_noise = Σ|X|² over remaining bins
SNDR = 10·log10(P_sig / (P_noise + P_harm))      (dB)
SNR  = 10·log10(P_sig / P_noise)                 (dB)
THD  = 10·log10(P_harm / P_sig)                  (dB)
SFDR = 10·log10(P_sig / max non-signal bin)      (dB)
ENOB = (SNDR − 1.76) / 6.02                       (bit)
```

ENOB derived this way is exact when the following hold (documented
assumptions):

* the input is a full-scale (or known-backoff) sine,
* quantization noise dominates and is white,
* there is no clipping,
* the record is coherent.

Under the same conditions the ideal N-bit result is
`SNDR = 6.02·N + 1.76 − backoff_dB`, which the test suite verifies to
within ±1 dB for N = 6…12.

### 7.3 Conversion latency

```
latency = T_acq + N·T_cycle          (wall-clock per conversion)
cycles  = N                          (SAR comparison cycles)
```

`T_cycle` is the simulated duration of one comparison cycle (configurable;
default 1 ns). When `fs` is given, latency is also expressed in sample
periods. Note that a pipelined SAR would hide most of this; the number here is
the single-conversion latency.

## 8. Nonidealities vs. ideal — comparison design

The default test signal is a coherent sine centred in the input range
(`dc = (v_min+v_max)/2`, amplitude `amp ≤ 0.49·Vref`), so nothing clips. The
`Simulator` runs the ideal quantizer and the SAR model on the *same* samples:

* ideal path: `qerr_ideal = v_in − recon(ideal_code(v_in))`;
* SAR path: `qerr_sar = v_held − recon(code)`, where `v_held` already
  contains the S/H nonidealities and `code` the DAC/comparator nonidealities.

Comparing the two isolates each effect: e.g. `qerr_sar` histogram widens
with comparator noise, INL/DNL grow with mismatch, the spectrum shows a noise
floor with jitter and harmonics with the slew nonlinearity.

## 9. Assumptions and limitations

* **Behavioral, not transistor-level.** This is an architectural simulator:
  no SPICE-level parasitics, charge injection, comparator meta-stability,
  settling transients inside the comparison cycle, thermal noise in the DAC
  array, or layout/process effects. Do not use it to predict absolute
  performance of a specific silicon implementation; use it to understand and
  teach the *structure* of the conversion and the first-order influence of
  each nonideality.
* **Noise sources are Gaussian and independent.** Real comparator noise is
  partially correlated across cycles; the first-order model ignores this.
* **Single-ended DAC.** No differential implementation, no common-mode
  effects, no reference loading.
* **Monotone weight assumption** for the closed-form INL: for
  `σ_u ≲ 0.5/2^N` the binary weights remain monotone with overwhelming
  probability; the ramp-based measurement does not rely on it.
* **Single-tone coherent testing.** SNDR on multi-tone or non-coherent
  signals needs the windowed measurement and slightly different
  bin-grouping; the implementation supports it but the theoretical anchor
  (§7.2) applies only to the coherent single-tone case.
* **Acquisition model is first-order RC.** No nonlinear switch resistance,
  no charge-sharing with the DAC array.
* **`slew_nl` is a behavioral distortion term**, not derived from device
  physics; it exists to demonstrate input-frequency-dependent distortion.

## 10. Reproducibility

Every stochastic draw (mismatch, comparator noise, jitter) uses a single
`np.random.default_rng(seed)` per `NonidealityConfig`; the same seed +
configuration reproduces identical codes and metrics bit-for-bit (tested).
